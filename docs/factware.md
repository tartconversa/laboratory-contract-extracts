# 检验事实仓设计

事实仓把陆续到达的交接记录按 `arrival` 重放为一串不可变快照。每个快照回答：
此刻哪些订单组有可引用的合格事实、采购能领取哪些数据批、送检同事还能补哪些实物
份额，以及发生了哪些影响通知。

## 分层

| 模块 | 职责 |
| --- | --- |
| `enums.py` | 份额、结果、送检、签收、证据形态的枚举与状态机 |
| `models.py` | 不可变身份对象：订单行、份额、分取、方法、结果、送检、签收 |
| `ingest.py` | 读取 CSV/TSV/JSONL，校验身份、枚举、引用完整性与修订号 |
| `units.py` | 量纲换算与区间；未检出表达为 `[0, 检出限]` 而非零 |
| `lineage.py` | 分取谱系、剩余克数、污染传播、混合基质推导 |
| `methods.py` | 方法对合同的五维覆盖核对 |
| `evidence.py` | 结果事实到四类证据的评价 |
| `evaluation.py` | 独立性账本与订单行组、组合包装合格判定 |
| `worklist.py` | 按缺证原因检索可补实物份额 |
| `warehouse.py` | 事件重放、快照、通知、交付批与影响级联 |
| `cli.py` | 采购系统与送检同事使用的命令行 |

## 区间与证据形态

- 定量结果退化为单点区间 `[v, v]`；未检出为 `[0, 检出限×factor]`。
- 合格判定统一为“整段区间落入 `[0, upper]`”。检出限本身高于上限时，未检出也不能
  证明符合（`detection_limit` 维度失败）。
- 证据评价顺序：撤回（无结果）优先于污染判定——报告撤回是独立事实，不被随后的份额
  污染抹掉；污染份额上的其他结果记为样本破坏；方法五维不通过记测法不适用。

## 独立性账本

独立性在**每个订单组内部**成立，按“实际使用的份额身份”记账，而不是按实物根粗粒度
锁定：

- 份额被某资格消耗后，它自身和它的派生物（`subtree` 向下）不能再证明组内另一资格。
- 同一父样的不同分取支是互相独立的份额：S11 被混合覆盖消耗，不锁死兄弟支 S13，也不
  锁死父样 S01 本身；但若 S01 先被消耗，S11/S13 即不可另立资格。
- 混合覆盖（`pool:<sample>:<lots>`）整体作为一份份额消耗，实际用量只记一次，同组内
  不能再充当第二份独立试样。
- 跨订单组不共享账本：不同采购结论各自取得独立证据；同批供货的跨组证明只能来自合同
  认可的覆盖关系，份额复用本身不隐含同批结论。

## 组合包装与混合覆盖

订单组内全部为 `pooled=yes` 的行才走混合覆盖路径：候选混合样的来源批次集合必须恰好
等于组内合同批次集合，且对每一行都形成合格证据（基质按 `mixed-<基质>` 记号与方法表
核对）。任一非 pooled 行缺证，或某部件对不上试样，整组不出合格事实。混合候选不合格
时继续尝试其他候选，全部失败再回退到逐行独立评价。

## 送检占用

送检单按 `dispatch` 身份取最新状态。`allocated`、`received`、`cancel_requested` 都仍
占用份额；只有 `cancel_ack` 释放。占用不否定该份额上已经产生的结果，只在缺证工作清单
中阻止把它再当作另一次检验的可用份额（`dispatch_held`）。

## 通知与交付批

- 仅当某组从“上一时刻合格”翻转为“当前缺证”时发通知，避免重复打扰。
- 已入库（`accepted`）组发 `freeze_recheck`：历史凭据原样保留在旧快照，冻结后续批次
  并安排重新送检；补测恢复合格后解除冻结。
- 仅 `offered` 未签收组发 `offer_invalidated`：旧合格批标记为不可领取，不能用于入库。
- 交付批 `B<arrival>-<group>` 只在合格性翻转或有签收事实时产生，带 `supersedes` 取代
  链；`claimable` 只取决于当前是否合格。

## 后续到货

新批次只需沿用同一套交接文件与合同字段进入新目录，仓库自动重放完整链路，保留每次
采购结论与当前检验状态的追溯关系。`tests/test_future_arrivals.py` 用合成目录演示了
错方法阻断、正确方法补测合格、签收后污染冻结、独立替代份额恢复的全过程。
